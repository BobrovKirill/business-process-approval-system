# Business Process Approval System

Курсовая работа: «Разработка системы автоматизированного управления бизнес-процессами с настраиваемыми маршрутами согласования».

Пока создан только стартовый каркас: Angular 21, NestJS 11 и общий пакет контрактов. Бизнес-логика, база данных и маршруты согласования будут спроектированы отдельно.

## Структура

```text
frontend/   Angular, TypeScript, SCSS, маршрутизация
backend/    NestJS, TypeScript, HTTP API
contracts/  @project/contracts — общие типы запросов и ответов
```

Это монорепозиторий на npm workspaces с одним корневым `package-lock.json`. Зависимости устанавливаются из корня.

## Запуск

Нужен Node.js 22.13.1 (версия зафиксирована в `.nvmrc`) и npm 10+. Если используется nvm:

```sh
nvm install
nvm use
npm ci
npm run dev
```

При первой загрузке репозитория `npm ci` устанавливает зависимости из lock-файла. В уже подготовленной папке достаточно `npm run dev`.

- Интерфейс: http://localhost:4200
- Проверка API: http://localhost:3000/api/health — ответ `{ "status": "ok" }`
- Остановка всех процессов: `Ctrl+C`.

Команда `dev` сначала собирает контракты, затем запускает их пересборку, NestJS и Angular с отслеживанием изменений. Angular перенаправляет запросы `/api/**` на локальный бэкенд через `frontend/proxy.conf.json`.

## Команды из корня

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запуск всего проекта |
| `npm run dev:frontend` | Запуск только Angular; API запускается отдельно |
| `npm run dev:backend` | Запуск только NestJS |
| `npm run build` | Последовательная сборка контрактов, бэкенда и фронтенда |
| `npm test` | Unit-тесты бэкенда и фронтенда |
| `npm run test:e2e` | Проверка HTTP-эндпоинта NestJS |
| `npm run lint` | Проверка стиля и правил TypeScript в бэкенде |

## Общие контракты

Оба приложения используют локальный workspace-пакет:

```ts
import type { HealthResponse } from '@project/contracts';
```

Контракты описывают границу API и не зависят от Angular, NestJS или моделей базы данных. Сейчас добавлен только `HealthResponse` для проверки связи приложений. TypeScript-типы не заменяют проверку входящих данных во время выполнения.

## Сборка

Результаты находятся в `frontend/dist/frontend/browser`, `backend/dist` и `contracts/dist`. Собранный бэкенд запускается командой `npm run start:prod --workspace backend`.

Прокси Angular работает только при локальной разработке. Для публикации фронтенда потребуется отдельно настроить обслуживание статических файлов и перенаправление `/api` на бэкенд. CI/CD пока не настроен.
